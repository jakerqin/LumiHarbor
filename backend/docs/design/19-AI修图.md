# AI 修图与生图

用云端图像模型给素材「微调」：老照片修复、去路人、换背景、调色调；也能用文字（可带参考素材）生成新图。
**原图永远不改**：修图结果存成素材的一个版本，用户决定是否设为当前显示，随时切回原图。

## 职责边界

- **负责**：调用 OpenAI Images API、预设提示词、任务状态、素材版本的保存与切换、生图结果入库
- **不负责**：本地模型推理、涂抹区域的局部重绘（mask）、费用精确核算、视频和音频

关键文件：

- 服务：[`services/ai_image/`](../../app/services/ai_image/) —— `client.py`（OpenAI 封装）、`presets.py`（预设）、`service.py`（任务）、`versions.py`（版本）
- 路由：[`routers/ai_image.py`](../../app/routers/ai_image.py)
- 任务：[`tasks/ai_image_tasks.py`](../../app/tasks/ai_image_tasks.py)（taskiq 任务名 `ai_image`）
- 模型：`model/asset_version.py`、`model/ai_image_job.py`，以及 `assets.current_version_id` 列
- 升级已有库：[`scripts/migrations/20261014_ai_image.sql`](../../../scripts/migrations/20261014_ai_image.sql)

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/ai-image/status` | `enabled`（总开关打开且已配置 Key）、预设列表、模型名 |
| POST | `/ai-image/jobs` | 建任务并投递 Worker，立即返回；403 未开启，429 超出每日上限，400 参数不合法 |
| GET | `/ai-image/jobs/{id}` | 轮询任务状态：pending / running / success / failed，失败原因在 `error_message` |
| GET | `/assets/{id}/versions` | 原图排第一；还没修过图时只返回一行虚拟原图（`id=0`） |
| PUT | `/assets/{id}/current-version` | `{version_id}`，为空或传原图行的 ID 表示切回原图 |
| DELETE | `/assets/{id}/versions/{vid}` | 删除 AI 版本及其文件；原图不能删；删的是当前版本时先切回原图 |

## 数据流

```text
POST /ai-image/jobs ─ 校验（总开关 / Key / 每日上限 / 预设与描述 / 只支持图片）
   │  修图：在建任务时按当前显示图的宽高比算好输出尺寸
   ▼
ai_image_jobs(pending) ─kiq─▶ ai_image_task（不自动重试：按次计费，失败原因交给用户决定）
   ├─ edit：FaceService.resolve_infer_path（preview 优先 = 当前版本，所以可以在上次结果上接着修）
   │        → 缩到长边 2048 的 PNG → images.edit
   │        → processed/versions/{asset_id}/v{id}.webp + 缩略图 → asset_versions 新增一行（不自动切换）
   └─ generate：参考素材（≤4）→ 有参考图走 images.edit，没有走 images.generate
            → 临时目录 → AssetImportService 正常入库 → 打 ai_generated 标签
```

任务行本身就是日志：`task_logs.asset_id` 是必填的，而生图没有源素材，所以不记在那里。

## 设计决策

### 为什么修图结果存成「版本」，而「设为当前」只改两个路径？

全站有 19 处用 `assets.thumbnail_path / preview_path` 生成图片地址（列表、首页、相册、地图、笔记……）。切换版本时只改这两个字段，所有地方就都显示新版本，不需要逐处改代码。
`original_path`、`file_hash`、语义向量、人脸、感知哈希都不动：版本只是展示层的东西，素材的身份仍然由原图决定。
原图原本的缩略图和预览路径存在 `kind=original` 那一行（第一次修图时自动创建），切回原图时用它恢复。

### 为什么默认用 gpt-image-2.5-flare + medium？

GPT Image 2.5（2026-09-08 发布）在 API 里分成两个型号：flare 是官方推荐的默认型号，延迟比 gpt-image-2 低一半；sunburst 面向精细编辑，更慢。
第三方资料显示两者单价相同，日常修图用 flare 性价比最高；「精细」档只是把 quality 提到 high。需要更精细的效果时，改 `AI_IMAGE_MODEL` 即可。

### 提示词怎么写？

参考 [awesome-gpt-image-2](https://github.com/freestylefly/awesome-gpt-image-2) 的结构化写法：目标 → 必须保持不变的部分 → 约束。
修图类提示词统一追加 `KEEP_IDENTITY`，要求保持人物身份、五官和构图不变。家庭照片里「人还是那个人」比修得好看更重要。
预设的提示词用英文写（模型对英文指令的遵循更稳定），名称和说明用中文给界面显示。没有拷贝参考仓库的案例内容，因为其中有第三方内容，各自的许可证不同。

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `OPENAI_API_KEY` | 空 | 为空时功能视为未开启 |
| `OPENAI_BASE_URL` | 空 | 为空走官方地址；也可以填兼容 OpenAI 接口的中转 |
| `AI_IMAGE_MODEL` | `gpt-image-2.5-flare` | 或 `gpt-image-2.5-sunburst` |
| `AI_IMAGE_QUALITY` / `AI_IMAGE_HQ_QUALITY` | `medium` / `high` | 「标准」和「精细」两档对应的 quality |
| `AI_IMAGE_DAILY_LIMIT` | 50 | 每人每天最多发起的任务数，填 0 表示不限 |
| `AI_IMAGE_TIMEOUT_SECONDS` | 300 | 单次调用的超时时间 |

总开关是 `task_definitions.ai_image`，在「设置 → 任务」里控制。

## 和其他模块的关系

- **素材列表和详情**：返回值新增 `current_version_id` 和 `ai_badge`（edited / generated），前端据此显示「AI」角标。
- **回收站**：版本文件留在 `processed/versions/{asset_id}/`，不随素材一起进回收站；到期清理时整个目录删除。如果当前显示的是某个版本，它的缩略图和预览会随素材一起进、出回收站。

## 已知限制

- 不支持涂抹区域的局部修改（mask），全部靠文字描述。
- 「下载」按钮下载的是原图；当前版本的图从版本条里的「下载当前版本」下载。
- 费用依赖 OpenAI 的计价，只用每日任务数上限兜底，不统计金额。
- 图片会上传到 OpenAI 或配置的中转，界面上已经提示，但不会逐次确认。
- `openai` SDK 固定在 3.22.1：model 和 quality 是按字符串传给服务端的，以后出新型号也不用升级 SDK。
