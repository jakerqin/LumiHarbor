# 工具层

位置：[`app/tools/`](../../app/tools/)

约定：这里放**无 FastAPI / 尽量无业务编排**的纯能力。可被 services、tasks、routers 调用；不要反过来依赖 routers。

## file_hash

文件：[`file_hash.py`](../../app/tools/file_hash.py)

用途：导入去重（精确/近精确内容识别）。

| 模式 | 条件 | 算法 |
|---|---|---|
| 完整 SHA256 | `< 100MB` 或 `smart_mode=False` | 8KB 分块流式 |
| 采样哈希 | `≥ 100MB` 且 `smart_mode=True` | 头 10MB + 尾 10MB（文件足够长时）+ `file_size` + `mtime` |

导入默认 `smart_mode=True`。采样不是密码学意义上的抗碰撞保证，而是在个人 NAS 场景用速度换可接受的去重精度。

## perceptual_hash

文件：[`perceptual_hash.py`](../../app/tools/perceptual_hash.py)

### MultiHashCalculator（现行主路径）

计算四种哈希：

| 字段 | 算法直觉 | 默认权重 |
|---|---|---|
| `phash` | DCT 结构 | 0.5 |
| `dhash` | 梯度边缘 | 0.3 |
| `average_hash` | 亮度均值 | 0.1 |
| `colorhash` | 颜色分布 | 0.1 |

综合距离：

```text
combined = 0.5*phash + 0.3*dhash + 0.1*average + 0.1*color
```

经验阈值（综合距离）：0–8 非常相似；8–12 相似；更大则逐渐视为不同。详情接口默认门槛 15。

- 图片：Pillow + imagehash（含 HEIF）
- 视频：ffmpeg 取**中间帧**再当图片算四哈希

### compute_visual_distance

详情页相似推荐走 [`services/similar.py`](../../app/services/similar.py)：视觉距离门槛 + 同日/同地/同相册加分。本文件只算距离。

- `compute_visual_distance`：四哈希齐全走加权，否则只比 phash
- `visual_percent`：把 0–64 距离换成百分比

## 设计决策

### 为什么多哈希加权？

单算法易被亮度/色调/压缩某一维度骗过；加权后结构（phash）占主导，颜色与亮度作辅助，降低误判。

### 为什么大文件采样哈希？

完整哈希百兆以上文件会拖垮导入吞吐；头尾 + 元数据在「同一导出管线产生的副本」场景通常足够区分。

## 已知限制

- 相似搜索是 O(n) 内存扫描，无汉明距离索引。
- 采样哈希理论上可能漏判「头尾相同、中部不同」的恶意构造文件（个人素材库可接受）。
