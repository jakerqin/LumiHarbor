# 笔记

## 职责边界

- **负责**：笔记创建/列表/详情/更新/软删；从 JSON 生成列表摘要；校验封面素材存在
- **不负责（当前）**：从 Markdown 解析 `asset://`、维护 `related_assets`、`include_assets` 聚合返回

关键文件：

- Router：[`routers/notes.py`](../../app/routers/notes.py)
- Service：[`services/note.py`](../../app/services/note.py)
- Schema：[`schema/note.py`](../../app/schema/note.py)
- Model：[`model/note.py`](../../app/model/note.py)

## 接口

前缀：`/notes`

| 方法 | 路径 | 职责 |
|---|---|---|
| POST | `/` | 创建 |
| GET | `/` | 列表（摘要 + 封面缩略图 URL） |
| GET | `/{note_id}` | 详情（完整 content + 高清封面） |
| PATCH | `/{note_id}` | 局部更新 |
| DELETE | `/{note_id}` | 软删 |

Query：`skip/limit`, `sort_by`（created_at / updated_at / shot_at）, `order`, `created_by`, `search`（标题模糊）。

## 数据模型要点

| 字段 | 角色 |
|---|---|
| `content` | **主存** Tiptap JSONContent |
| `content_markdown` | 可选副本，供预览或兼容旧前端 |
| `cover_asset_id` | 封面；创建/更新时校验素材存在 |
| `cover_position_x` / `cover_position_y` | 封面取景焦点 0–100（CSS `object-position`，默认 50）；只存焦点不重裁文件 |
| `related_assets` | 列存在，但 `create_note` 固定写 `None` |
| `shot_at` | 叙事时间，可与 `created_at` 分离（时间轴排序可用） |

列表摘要：`NoteService` / `_build_excerpt` 递归遍历 JSON 文本节点，截断约 160 字。

## 设计决策

### 为什么主存是 Tiptap JSON？

前端 Novel / Tiptap 编辑器原生产出 JSON；存 JSON 可无损保留节点结构（标题层级、marks）。Markdown 作为可选镜像，而不是唯一真相源。

### 为什么暂时不做 related_assets / include_assets？

字段预留了「正文引用素材」能力，但自动抽取与聚合尚未接线。与 CLAUDE.md 里旧的 Markdown `asset://` 描述不同——**以后端代码为准**。

## 依赖

```text
notes router
  → NoteService
  → AssetUrlProvider（封面 URL）
  → Asset 存在性校验
home/timeline → 直接查 Note 列表做时间轴（不是本 router，但共享模型）
```

## 已知限制

- `current_user_id = 1` 硬编码。
- 无正文内嵌素材协议的后端解析。
- 搜索仅标题 `LIKE`，不搜 JSON 正文。
- 加密字段 `is_encrypted` 未形成完整加解密链路。
