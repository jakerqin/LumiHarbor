# 应用入口与配置

## 职责边界

| 文件 | 职责 |
|---|---|
| [`run.py`](../../run.py) | 开发启动脚本：检查 Redis、可选启动 Worker、再起 uvicorn |
| [`app/main.py`](../../app/main.py) | FastAPI 实例：CORS、静态媒体、全局异常、注册路由 |
| [`app/config/config.py`](../../app/config/config.py) | `Settings`：环境变量 / `.env` |
| [`app/db.py`](../../app/db.py) | SQLAlchemy Engine、Session、`get_db` |
| [`start_worker.sh`](../../start_worker.sh) | 独立 Worker 进程管理 |

## 启动数据流

```text
python run.py
  │
  ├─ 加载 settings（.env）
  ├─ AUTO_START_WORKER?
  │     ├─ Redis ping 失败 → 跳过 Worker，仅起 API
  │     └─ 成功 → subprocess: taskiq worker app.tasks.broker:broker
  └─ uvicorn.run("app.main:app", host=0.0.0.0, port=8000, reload=True)
         │
         └─ 退出/信号 → terminate Worker
```

生产建议：`AUTO_START_WORKER=false`，用 `start_worker.sh` 或容器单独跑 Worker。

## main.py 做了什么

1. 创建 `FastAPI(title=settings.PROJECT_NAME)`
2. 挂 CORS（局域网放开 `*`）
3. 若 `NAS_DATA_PATH` 是目录：`StaticFiles` 挂到 `MEDIA_BASE_PATH`
4. 注册 `HTTPException` / 通用 `Exception` 处理器 → `ApiResponse.error`
5. `GET /` 欢迎信息
6. `include_router`：assets / albums / ingestion / management / home / tags / notes / map

路由聚合逻辑见 [`app/routers/__init__.py`](../../app/routers/__init__.py)：ingestion 的 scan 与 upload 先合并为一个 `ingestion_router`。

## 关键配置项

来源：`Settings`（pydantic-settings，`env_file=".env"`）

| 配置 | 默认/说明 | 影响 |
|---|---|---|
| `DATABASE_URL` | MySQL pymysql DSN | ORM 连接 |
| `DB_TIMEZONE` | `+08:00` | 连接 `init_command` |
| `NAS_DATA_PATH` | 本地/NAS 根目录 | 静态挂载、导入读写、缩略图路径 |
| `REDIS_*` | host/port/db/password | Taskiq 队列 |
| `AUTO_START_WORKER` | `true` | `run.py` 是否拉起 Worker |
| `WORKER_COUNT` | `2` | `run.py` 子进程 workers（`start_worker.sh` 默认 4） |
| `LOG_LEVEL` | `INFO` | Worker / uvicorn |
| `AMAP_API_KEY` | 空则走 Nominatim | 地理编码 |
| `PUBLIC_BASE_URL` | `http://localhost:8000` | 生成媒体绝对 URL |
| `MEDIA_BASE_PATH` | `/media` | StaticFiles 前缀 |
| `ASSET_URL_PROVIDER` | `local` \| `oss` | URL 策略 |
| `ASSET_STORAGE_PROVIDER` | `local`（`oss` 未实现） | 导入入库存储后端 |
| `OSS_PUBLIC_BASE_URL` | OSS 时必填 | CDN/对象 URL |
| `SECRET_KEY` 等 JWT 字段 | 预留 | **当前未接入鉴权** |

## 设计决策

### 为什么开发环境自动起 Worker？

导入后立刻需要 phash / geocoding。本地只起 API 会导致「导入成功但哈希永远空」。`run.py` 用子进程绑定生命周期，降低「忘了起 Worker」的概率；生产再拆开，避免 reload 与多 Worker 抢同一进程树。

### 为什么配置用 pydantic-settings？

类型校验 + `.env` 加载 + 单例 `settings`，避免各处 `os.getenv` 散落默认值不一致。

## 已知限制

- uvicorn `reload=True` 时，Worker 子进程不会随代码热重载自动重建（改 tasks 后可能需要重启 `run.py`）。
- 静态媒体目录不存在时只打 warning，API 仍启动，但图片 URL 会 404。
- 无应用级 health 与 Worker 健康联动；`/management/health` 只查 DB。
