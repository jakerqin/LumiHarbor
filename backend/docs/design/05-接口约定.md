# Schema 与 API 约定

位置：[`app/schema/`](../../app/schema/)

## 组织方式

| 文件/包 | 用途 |
|---|---|
| `common.py` | 泛型 `ApiResponse[T]` |
| `asset.py` | `AssetOut`、分页、批量删除请求 |
| `album.py` | 相册 CRUD / 素材关联 / 排序枚举 |
| `note.py` | 笔记创建更新（Tiptap JSON）与摘要/详情 |
| `tag_definition.py` | 标签元数据输出 |
| `map.py` | 足迹点、详情、统计 |
| `home/featured.py` | 精选素材（camelCase alias） |
| `home/timeline.py` | 时间轴笔记条目 |
| `ingestion/scan.py` | 扫描请求与结果统计 |

`schema/__init__.py` 聚合导出常用类型；home / ingestion 子包也可单独 import。

## 成功响应写法

路由层典型模式：

```python
return ApiResponse.success(data=page_response)
```

前端读取：`const res = await apiClient.get<T>(...);` 然后使用 `res.data`（已被解包为 `result`）。  
**不要**再写 `response.data.result`。

## 分页形态（不完全统一）

后端存在两套习惯，改接口时保持所属模块一致：

| 风格 | 典型字段 | 使用模块 |
|---|---|---|
| page / page_size | `page`, `page_size`, `total`, `has_more`… | assets |
| skip / limit | `skip`, `limit`, `total`, `has_more` | albums, notes |

## 关键业务 Schema 要点

### AssetOut

在模型字段之外附加：

- `original_url` / `thumbnail_url` / `preview_url`（由 URL Provider 生成）
- 可选标签摘要、收藏状态等（由 `AssetService.build_asset_dict` 填充）

### Note

- `content: Dict` = Tiptap JSONContent（创建必填）
- 笔记主存 Tiptap JSON；`content_markdown` 可选且前端不再写入
- 列表用 `NoteSummaryOut.excerpt`（从 JSON 抽纯文本），详情再带完整 `content`

### FeaturedResponse

- 字段使用 camelCase alias（如 `userId`）
- **不包在 ApiResponse 里**（历史例外）

### ScanRequest

- `source_path`, `created_by`, `visibility`
- `import_to_album` + `album_info`
- `default_gps`（元数据缺 GPS 时覆盖）

## 依赖关系

```text
routers ──使用──▶ schema（入参/出参类型）
services ──产出──▶ dict / model，再由 router 或 service 组装为 schema
前端 ──约定──▶ ApiResponse 解包（见 conventions.md）
```

## 已知限制

- `FeaturedResponse` 与统一壳不一致，前后端改一侧必须同步。
- Schema 注释若写「Markdown 主存」以过时论——以 `note.py` 字段类型为准。
- 部分列表接口的筛选参数在 Router 声明了但未实现（例如 assets 的 `location`，见 [素材库](./07-素材库.md)）。
