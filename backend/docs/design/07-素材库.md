# 素材库

## 职责边界

- **负责**：素材查询展示、收藏、相似搜索、批量软删、地标字典读取入口
- **不负责**：物理导入（见 [素材导入](./06-素材导入.md)）、相册归属（见 [相册](./08-相册.md)）

关键文件：

- Router：[`routers/assets.py`](../../app/routers/assets.py)
- Service：[`services/asset.py`](../../app/services/asset.py)
- 相似算法：[`services/similar.py`](../../app/services/similar.py) + [`tools/perceptual_hash.py`](../../app/tools/perceptual_hash.py)

## 接口一览

前缀：`/assets`

| 方法 | 路径 | 职责 |
|---|---|---|
| GET | `/` | 分页列表 + 筛选 + 可选 `q` 混合搜索 + 收藏态 |
| GET | `/locations` | `location_poi` 字典值列表 |
| GET | `/{asset_id}` | 详情 |
| GET | `/{asset_id}/tags` | 该素材全部 tag_key/value |
| GET | `/{asset_id}/similar` | 多哈希相似搜索 |
| GET | `/{asset_id}/faces` | 该素材检出的人脸 / 动物脸 |
| POST | `/{asset_id}/favorite` | 收藏（已有软删行则复活，`uk_user_asset` 不含 `is_deleted`，不能重插） |
| DELETE | `/{asset_id}/favorite` | 取消收藏（软删收藏行） |
| POST | `/batch-delete` | 批量软删 |

### 列表常用 Query

| 参数 | 说明 |
|---|---|
| `page` / `page_size` | 分页（默认 page_size 与前端瀑布流对齐时常为 30） |
| `user_id` | 默认 `1`，用于收藏态 |
| `asset_type` | `image` / `video`… |
| `location_poi` | 按标签值筛 |
| `shot_at_start` / `shot_at_end` | 拍摄时间范围 |
| `sort_by` / `sort_order` | 默认 `created_at` |
| `is_favorited` | 仅看收藏 |
| `q` | 语义 + 文件名/地点/成员名混合检索；空则走原时间线 |
| `location` | **已声明但未实现**；勿依赖 |

## 核心流程

### 列表序列化

```text
DB 查询 assets（is_deleted=false + 筛选）
  → AssetService.batch_query_asset_tags（默认 aspect_ratio / location_city / location_poi）
  → batch_query_favorited_ids(user_id)
  → build_asset_dict（补 URL / 标签 / 收藏）
  → AssetsPageResponse 包进 ApiResponse
```

### 相似搜索

```text
取目标素材
  → AssetSimilarService.find
  → 候选：最近有 phash 的同类型 + 同日 + 同相册 + 同城/同地标
  → 视觉距离（四哈希加权，缺则只比 phash）≤ threshold（接口默认 15）
  → 排序：视觉百分比 + 同日/同地/同相册加分
  → 展示 similarity 仍是视觉百分比，加分只影响名次
```

### 批量软删

`AssetService.batch_delete_assets`：

1. 软删 `assets`
2. 级联软删 `album_assets` / `asset_tags` / `user_favorites`
3. 可选把物理文件挪到 `recycle_bin/{timestamp}/asset_{id}/`
4. 清理不再被引用的 `metadata_dictionary.location_poi`
5. 级联软删 `faces`；删除 `assets_clip` 点（匹配脸不进 Qdrant）

人脸裁剪图 `processed/faces/{asset_id}_*.webp` 不进回收站（恢复后还要用），由到期清理删除。

### AI 修图字段

列表 / 详情返回 `current_version_id`（当前展示的 AI 版本，空为原图）和 `ai_badge`（`edited` / `generated`，来自 `current_version_id` 与 `ai_generated` 标签）。版本切换会改 `thumbnail_path` / `preview_path`，见 [19 · AI 修图](./19-AI修图.md)。

### 回收站

代码在 [`services/trash/`](../../app/services/trash/)，路由 [`routers/trash.py`](../../app/routers/trash.py)，前缀 `/trash`：

| 方法 | 路径 | 职责 |
|---|---|---|
| GET | `/trash` | 文件还在 `recycle_bin/` 里的已删除素材，按删除时间倒序；带 `days_left`、`restorable`/`reason` |
| POST | `/trash/restore` | `{asset_ids}` → `{restored, failed[{asset_id, reason}]}` |

- **删除时间**取回收站目录名（`recycle_bin/{%Y%m%d_%H%M%S}/asset_{id}/`）；数据库没有单独的删除时间列。
- **恢复**：文件挪回原相对路径 → `assets.is_deleted=false` → 标签、相册关系、人脸中 `updated_at` 不早于素材行 `updated_at`（删除时同一次提交写入）的行一起恢复（删除前就单独删掉的不会被带回）→ 刷新相册时间范围/封面 → 重新加入 `location_poi` 字典 → 清空 `clip_model` 并重新发 `compute_clip`。
  - 收藏**不恢复**：`user_favorites` 没有更新时间列，分不清是随素材删的还是之前就取消的。
  - 不能恢复：同一文件（`file_hash`）删除后又被导入过（恢复会重复）；原位置已有文件。
- **到期清理**（[`purge.py`](../../app/services/trash/purge.py)）：删除时间超过 `RECYCLE_RETENTION_DAYS`（默认 90，0 关闭）的素材，删除回收站目录和人脸裁剪图。**数据库记录保留为已删除**，不做物理删除。后端启动时清理一次，之后每 24 小时一次（后台线程）；已恢复的素材不碰。手动预览/执行：`python scripts/purge_recycle_bin.py [--days N] [--apply]`。

`q` 混合检索见 [18 · 语义搜索](./18-语义搜索.md)。

## 设计决策

### 为什么列表标签只取一小撮 key？

瀑布流卡片只需要宽高比与地点摘要；全量标签走 `/{id}/tags`，避免列表 N×标签膨胀。

### 为什么相似搜索在应用层算距离？

感知哈希没有现成的 MySQL 汉明距离索引方案；数据量个人库可接受「取子集 + 内存算」。后续若库很大再考虑专用索引/近似检索。

## 依赖

```text
assets router
  → AssetService / AssetUrlProvider
  → MetadataDictionaryService（/locations）
  → UserFavorite / AssetTag 直接查询（部分端点）
  → AssetSimilarService / compute_visual_distance
  → SearchService（有 `q` 时）
```

## 已知限制

- 回收站只认文件还在 `recycle_bin/` 的素材：删除时 NAS 未配置、文件早已缺失的素材不会出现在回收站，也没法恢复。
- 素材删除后若 `assets` 行又被其他流程更新过，恢复时按时间识别的级联行可能漏掉（目前没有这种写入路径）。

- `location` 城市筛未接；用 `location_poi` 或后续扩展标签筛。
- 无真实鉴权；删改仅靠传入的 `user_id`。
- 相似搜索 O(n) 扫描，数据量上升后需改造。
- 同日/同地/同相册只加权排序；视觉距离仍过不了阈值的，不会仅因同一相册出现。
