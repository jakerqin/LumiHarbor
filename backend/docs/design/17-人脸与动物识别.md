# 人脸与动物识别

列表与详情展示见前端 [15-面孔](../../../frontend/docs/design/15-面孔.md)。

## 职责边界

- **负责**：维护家人 / 猫狗名单、登记参考向量、导入时检出后与名单比对，命中才写 `faces`
- **不负责**：自动聚类、路人收件箱、熊/鸟入库、CLIP 语义检索、OCR、替换 phash 相似

关键文件：

- Router：[`routers/subjects.py`](../../app/routers/subjects.py)、[`routers/faces.py`](../../app/routers/faces.py)、`POST /management/faces/backfill`
- Service：[`services/subject.py`](../../app/services/subject.py)、[`services/face.py`](../../app/services/face.py)、[`services/vector_store.py`](../../app/services/vector_store.py)
- 引擎：[`tools/face/`](../../app/tools/face/)
- 任务：[`tasks/face_detection_tasks.py`](../../app/tasks/face_detection_tasks.py)

## 为什么是名单而不是扫出所有脸

家庭相册里的路人、熊、鸟、背影没有产品价值。名单为空时导入 0 张脸。登记只走上传照当场检脸，框不落库。

## 两套模型、两个名单 collection

| collection | 维度 | 用途 |
|---|---|---|
| `subjects_human` | 512 cosine | 家人登记照（InsightFace `buffalo_s`） |
| `subjects_pet` | 768 cosine | 猫/狗登记照（AnyFace 脸 + DINOv2） |
| `clip` | （预留） | Phase 2，本轮不创建 |

匹配脸只进 MySQL `faces.subject_id`，不再为每张检出 upsert 旧的 `faces_human` / `faces_animal`。启动时会删掉这两个旧 collection。

人：InsightFace。动物：AnyFace 出脸后只留 COCO `cat`/`dog`。无对应 kind 的成员则跳过该通道。阈值：人 0.32，宠物 0.50。同一张图同一成员只留最高分。推理用 preview / 原图，视频跳过容器文件。裁剪外扩：人 0.32、宠物 0.45（登记照仍按用户框、padding=0）。

## 数据流

```text
登记
  → 上传照当场检脸点选
  → subject_refs + Qdrant 名单向量

导入出缩略图
  → Taskiq detect_faces
  → 名单为空则写 0 张脸
  → 检出 → 名单 top1
  → 命中写 faces + crop；未命中丢掉
```

## 接口

一律 `ApiResponse`。`user_id` 未鉴权，默认 `1`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/subjects` | 成员列表 / 创建（`kind=human\|pet`，宠物必填 `species=cat\|dog`） |
| GET/PATCH/DELETE | `/subjects/{id}` | 详情、改名、软删（级联脸与登记照向量） |
| POST | `/subjects/face-candidates` | 上传图当场检脸，不落库 |
| POST | `/subjects/{id}/refs` | multipart 登记照；可带 `bbox_*` 指定哪张脸 |
| GET | `/subjects/{id}/faces` | 该成员已匹配脸分页 |
| GET | `/assets/{id}/faces` | 该素材已匹配脸 |
| GET | `/faces` | 已匹配脸分页；可选 `subject_id` / `subject_type` |
| POST | `/management/faces/backfill` | 补发 `detect_faces`（匹配才写入）；可选 `shot_at_from` / `shot_at_to`，`missing_only=false` 会重扫已匹配过的图 |

登记上传会在 API 进程加载 InsightFace / AnyFace（登记低频）。

已有库执行 [`scripts/alter_add_subjects.sql`](../../../../scripts/alter_add_subjects.sql)（会软删未挂 `subject_id` 的旧脸）。

## Qdrant

与 MySQL / Redis 同一套 [`docker-compose.yml`](../../../../docker-compose.yml)：`QDRANT_URL=http://localhost:6333`。模型不进 Qdrant 容器。

## 动物脸检测

只服务已登记的猫狗。AnyFace 扫脸 + COCO 补 `species`，不是 cat/dog 则丢掉（含人、熊、鸟、空种类）。缺 `animal_face_det.onnx` 时跳过宠物通道。

```text
backend/models/          # gitignore
  buffalo_s/
  animal_face_det.onnx
  coco_det.onnx
  animal_embed.onnx
```

## 人脸过滤

InsightFace `det_thresh=0.62`，`MIN_BBOX_SIDE=0.04`。远景小人可能被滤掉。

## 已知限制

- 16GB M4 建议 `WORKER_COUNT=1`
- 宠物个体仍是 DINOv2，同种多只可能混；多登记几张正脸会好一些
- 合影里小动物脸可能漏检
- `species` 靠 COCO，标注不准时猫狗也可能对不上
- 名单阈值上线后按误匹配再调
- 检脸读图会按 EXIF 转正（iPhone 竖拍原图否则是横着的，AnyFace 会漏）
- 检脸用 preview / 原图，不用缩略图（缩略图 embedding 对不上登记照）
- Taskiq Worker 不随 uvicorn 热重载；改检测代码后要重启 `./start.sh`
