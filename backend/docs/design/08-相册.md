# 相册

## 职责边界

- **负责**：相册生命周期；相册内素材增删改序；封面与起止时间维护
- **不负责**：素材文件导入本身（导入模块可调用本服务「导入到相册」）

关键文件：

- Router：[`routers/albums.py`](../../app/routers/albums.py)
- Service：[`services/album.py`](../../app/services/album.py)
- Schema：[`schema/album.py`](../../app/schema/album.py)

## 接口一览

前缀：`/albums`

| 方法 | 路径 | 职责 |
|---|---|---|
| POST | `/` | 创建 |
| GET | `/` | 列表（封面 URL、asset_count） |
| GET | `/{album_id}` | 详情 |
| PUT | `/{album_id}` | 更新元信息 |
| DELETE | `/{album_id}` | 软删相册（实现上会级联处理关联素材，详见服务代码） |
| GET | `/{album_id}/assets` | 相册内素材 |
| POST | `/{album_id}/assets` | 添加单个 |
| POST | `/{album_id}/assets/batch` | 批量添加 |
| DELETE | `/{album_id}/assets/{asset_id}` | 移除关联 |
| PUT | `/{album_id}/assets/{asset_id}/sort` | 更新 sort_order |
| PUT | `/{album_id}/cover` | 手动设封面 |

列表筛选：`skip/limit`, `sort_by`, `order`, `visibility`, `search`, `created_by`, 时间范围等。

## 自动维护规则

```text
添加/移除素材之后：
  _update_album_time_range
    → start_time = min(shot_at), end_time = max(shot_at)

封面为空时：
  _update_album_cover_if_needed
    → 选最早 shot_at 的关联素材
```

导入场景还会走 `get_or_create_album`：按 id 或 name 复用/创建，再 `add_assets_to_album_batch`。

## 设计决策

### 为什么时间范围冗余在相册上？

列表页要展示「这次旅行从哪天到哪天」，每次 JOIN 聚合太贵；写入路径维护两次字段换读取便宜。

### 为什么封面可自动可手动？

自动保证新相册立刻有封面；手动满足「我想用某一张当封面」而不被后续添加打乱（手动设置后逻辑以服务实现为准）。

### 封面取景焦点

`cover_position_x` / `cover_position_y`（0–100，默认 50）对应前端 CSS `object-position`，只存焦点不重裁文件。创建/更新相册时可写入；换封面素材时前端重置为居中。

## 依赖

```text
albums router → AlbumService → Asset / AlbumAsset
             → AssetService / AssetUrlProvider（列表封面与素材序列化）
ingestion → AlbumService.get_or_create_album / add_assets_to_album_batch
```

## 已知限制

- `current_user_id = 1` 硬编码（创建者），待鉴权中间件。
- 删除相册的级联策略较激进（会触发素材批量删除路径）——改删除语义前务必读 `AlbumService.delete_album` 全文，避免误伤素材库。
