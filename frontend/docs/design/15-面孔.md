# 面孔

路由：

- 成员墙 [`app/(main)/faces/page.tsx`](../../app/(main)/faces/page.tsx)
- 成员详情 [`app/(main)/faces/[id]/page.tsx`](../../app/(main)/faces/[id]/page.tsx)
- 素材详情匹配条在 [`assets/[id]/page.tsx`](../../app/(main)/assets/[id]/page.tsx)

## 职责边界

- **负责**：成员墙（圆框头像 / 名字 / 张数）；添加 / 删除成员；上传登记照；展示已匹配裁剪；新建成员后询问历史补算范围
- **不负责**：路人收件箱、自动聚类、点脸做向量搜、素材页当场点选登记

关键文件：

- API：[`lib/api/subjects.ts`](../../lib/api/subjects.ts)、[`lib/api/faces.ts`](../../lib/api/faces.ts)
- 成员卡：[`components/faces/SubjectCard.tsx`](../../components/faces/SubjectCard.tsx)
- 登记：[`AddSubjectModal.tsx`](../../components/faces/AddSubjectModal.tsx)、[`ScanHistoryModal.tsx`](../../components/faces/ScanHistoryModal.tsx)
- 匹配条：[`AssetFacesStrip.tsx`](../../components/assets/AssetFacesStrip.tsx)
- 导航：`MAIN_NAV` 项「成员墙」→ `/faces`

## 数据流

```text
/faces
  ├─ GET /subjects → 成员卡 → /faces/{id}
  │    └─ GET /faces?subject_id= → FaceCard → /assets/{asset_id}
  └─ 添加成员 → POST /subjects → 可选上传照 POST /face-candidates + /refs
       └─ ScanHistoryModal → POST /management/faces/backfill

/assets/:id
  └─ GET /assets/{id}/faces → 已匹配名条
```

后端契约见 [后端 17](../../../backend/docs/design/17-人脸与动物识别.md)。成员墙走 `GET /subjects`，不要扫全部素材。

## 列表页

成员墙按头像读：圆框封面，名字和张数写在图下，三点菜单挂在圆外。匹配网格仍是圆角方卡（点进原图的照片）。页头图标按钮对齐相册。

| 能力 | 实现 |
|---|---|
| 壳 | `PageShell` + `PageHeader` |
| 筛选 | 无；人和猫狗都算家人 |
| 添加 | 名字 + 头像；人和猫狗都检出，点选后预填物种（人/猫/狗），可改；选中框可拖、可拉角 |
| 历史扫描 | 新建成员后询问：按拍摄日期 / 全部素材 / 暂不扫描；走 `POST /management/faces/backfill`（`missing_only=false`） |
| 删除 | 卡片三点菜单 / 详情页图标按钮；确认后软删成员、登记照与已匹配裁剪 |
| 点击 | 进该成员匹配照片 |

## 素材详情

主图下、相似推荐上。音频跳过。0 条整块不渲染。缩略图用圆框（身份条，和相似推荐的方卡区分）。可点进 `/faces/{subject_id}`。

## 设计决策

登记只走 `/faces` 上传照。导入时匹配名单才写 `faces`。

## 已知限制

- 底栏 8 项较挤
- 第一次上传登记照会加载模型，可能要等十几秒
- Worker 未重启时新导入可能仍用旧逻辑
- 历史补算单次最多排队 10000 张；日期按 `shot_at`，没有则用入库时间
