# 笔记

路由：

- 列表 [`app/(main)/notes/page.tsx`](../../app/(main)/notes/page.tsx)
- 新建 [`app/(main)/notes/new/page.tsx`](../../app/(main)/notes/new/page.tsx)
- 详情编辑 [`app/(main)/notes/[id]/page.tsx`](../../app/(main)/notes/[id]/page.tsx)

## 职责边界

- **负责**：笔记列表（网格/时间轴）、创建与自动保存、详情内联编辑、封面素材选择
- **不负责**：标签筛选（笔记模块无 tags UI）；独立 `/notes/novel` 体验页（**已不存在**）
- **编辑器实现细节**：见 [Novel 编辑器与 AI](./10-Novel编辑器与AI.md)

## 内容模型（与后端对齐）

| 字段 | 前端用法 |
|---|---|
| `content` | **主存** `JSONContent`（novel/tiptap） |
| `cover_asset_id` | 封面；新建流通过 `AssetPickerModal` 选择 |
| `cover_position_x` / `y` | 封面取景焦点（`CoverFocalEditor` → `object-position`）；换封面重置 50/50 |
| `excerpt` | 列表卡片摘要（后端从 JSON 抽） |

**不再**以 Markdown 源码编辑 + Streamdown 预览作为主路径；`NoteMarkdown` 组件已不存在。

## 新建页

[`NoteEditor`](../../components/notes/NoteEditor.tsx) 组合：

```text
NotePaperShell
  NoteCoverImage（CoverFocalEditor）+ NoteTitleInput + TailwindAdvancedEditor
  └─ 防抖自动保存（标题/封面/焦点/正文变化后约 2s）
       → createNote（首次）或 updateNote（已有 noteId）
       提交 content + cover_asset_id + cover_position_*
```

导航条：[`NoteEditorNavbar`](../../components/notes/NoteEditorNavbar.tsx) → `NoteBackButton`。

## 详情页

- 拉 `notesApi.getNote(id)`（**无** `include_assets` 参数——后端该能力当前也未作为主路径）
- 标题与「今天修改」等元信息在深色编辑面内（封面可选）
- 封面：`cover_preview_url` → `cover_original_url` → thumbnail；可拖拽调焦点并 PATCH `cover_position_*`
- 正文：`NotePaperShell` + `TailwindAdvancedEditor`，`onSave` → `updateMutation`（同样写 markdown 副本）
- 详情页**当前不换封面/改标题**（与新建页的 `NoteEditor` 完整壳不同），但可调取景

## 正文内嵌素材

编辑器通过 Slash / `window.openAssetPicker` 打开 `AssetPickerModal`，插入：

- 图片：`image` 节点，`attrs.src` = 媒体绝对 URL，`attrs.assetId`
- 视频：自定义 `video` 节点，同上

**不是** Markdown `![](asset://{id})` 协议。`asset://` 相关代码仍在 `lib/markdown/`，但主笔记流未使用（见 [Markdown 与素材协议](./11-Markdown与素材协议.md)）。

## 数据流

```text
/notes
  → GET /notes?skip&limit&sort_by=updated_at

/notes/new
  → NoteEditor 自动保存
       POST /notes 或 PATCH /notes/{id}

/notes/:id
  → GET /notes/{id}
  → 编辑器防抖 PATCH /notes/{id}
```

## 设计决策

### 为什么主存 JSON 而不是 Markdown？

与后端一致：Novel/Tiptap 原生产出 JSON，可保留标题层级、marks、自定义 video 节点。Markdown 作检索/兼容副本。详见后端 [笔记](../../../backend/docs/design/笔记.md) 与本文档 Novel 篇。

### 为什么详情与新建不是同一套壳？

新建需要标题/封面/创建态；详情强调阅读+正文编辑。后续可把封面/标题编辑收敛进详情，避免两套保存路径漂移。

## 依赖

```text
notes pages
  → notesApi
  → NoteEditor / NoteGrid / NoteTimeline
  → novel-native/TailwindAdvancedEditor
  → AssetPickerModal、mediaUrl
```

## 与文档差异（重要）

| CLAUDE.md / 旧说法 | 当前代码 |
|---|---|
| Markdown 源码 + Streamdown 预览 | Novel/Tiptap JSON 编辑 |
| `asset://` 正文协议 + `include_assets` | 插入绝对媒体 URL；无 include_assets |
| 独立体验页 `/notes/novel` | **路由不存在**；`NovelNativeEditor` 仅为薄包装且无页面引用 |
| tags 不做 | 仍正确 |

## 已知限制

- 详情页改标题/封面需补 UI；标题目前只读展示在编辑面内。
- 正文图片依赖后端媒体 URL 可访问性；离线/换域名后历史 JSON 内绝对 URL 可能失效（未存纯 assetId 解析层）。
- 列表页无搜索（后端支持 `search`，前端未接线）。
