# 素材库

路由：

- 列表 [`app/(main)/assets/page.tsx`](../../app/(main)/assets/page.tsx)
- 详情 [`app/(main)/assets/[id]/page.tsx`](../../app/(main)/assets/[id]/page.tsx)

## 职责边界

- **负责**：筛选浏览、无限滚动瀑布流、批量选择删除、回收站（`/assets/trash`）、本地上传（附可选 GPS）、单素材详情/标签/收藏/相似推荐
- **不负责**：文件夹扫描导入（相册「从文件夹导入」）；标签定义后台在 `/settings`

## 列表页能力

| 能力 | 实现 |
|---|---|
| 瀑布流 | [`AssetGrid`](../../components/assets/AssetGrid.tsx) → [`AssetMasonry`](../../components/assets/AssetMasonry.tsx) |
| 筛选栏 | [`AssetFilterBar`](../../components/assets/AssetFilterBar.tsx)：搜索框（`q`）+ 字段来自 `GET /templates/resolve?kind=filter`；默认仍是日期 / 地点 / 收藏 |

| 卡片 | [`AssetCard`](../../components/assets/AssetCard.tsx) + [`FavoriteButton`](../../components/assets/FavoriteButton.tsx) |

### 筛选模型

`AssetsFilter`（[`lib/api/assets.ts`](../../lib/api/assets.ts)）：

- `q`（语义 + 文件名/地点/成员名；回车搜索；空态「没有对上这句话」）
- `asset_type` / `location` / `location_poi`
- `shot_at_start` / `shot_at_end`
- `is_favorited`
- `sort_by` / `sort_order`（API 支持；当前 FilterBar 未暴露全部排序 UI）

地点选项来自 `GET /assets/locations`（Query `staleTime` 5 分钟）。

### 瀑布流与分页

```text
AssetGrid
  useQuery(['assets', page, pageSize, filter])
  pageSize = 30
  useInfiniteScroll(threshold=500) → page++
  累积 allAssets → AssetMasonry
```

`AssetMasonry`：**最短列优先**分配，用 `aspect_ratio` 估高；断点随视口列数变化：视口 ≤640 为 1 列、≤768 为 2 列、≤1280 为 3 列、≤1536 为 4 列，更宽 5 列（`defaultBreakpointColumns` 的 key 是 max-width）。相册详情复用同一组件；相册列表 `AlbumMasonry` 同样按 max-width 匹配（≤640 为 1、≤1024 为 2、≤1280 为 3，更宽 4）。

列表页使用 [`AssetFilterBar`](../../components/assets/AssetFilterBar.tsx)；改筛选优先改 FilterBar。

## 回收站 `/assets/trash`

[`app/(main)/assets/trash/page.tsx`](../../app/(main)/assets/trash/page.tsx)，数据走 [`trashApi`](../../lib/api/trash.ts)（`GET /trash`、`POST /trash/restore`）。

- 不进 Dock：从素材库进入，路由挂在 `/assets` 下，导航高亮仍是「素材」。
- 复用 `AssetMasonry`：`trashItemToAsset` 转成 `Asset`，常驻选择模式（点卡片即选中）；右上角用 `renderCornerBadge` 替换收藏按钮，显示「剩 N 天」（≤7 天标红），不能恢复的显示「已重新导入」，点它弹出原因、不可选。
- 页头说明保留天数（来自接口 `retention_days`）；有内容时显示数量与「全选」；选中后底部悬浮条与素材库批量条同款，操作只有「恢复」。
- 不提供「立即彻底删除」：到期由后端自动清理。

## 上传数据流

```text
选文件 → UploadAssetsModal
  ├─ 可选 MapPicker（高德）产出 LocationData
  └─ ingestionApi.uploadFilesSequentially(files, { locationData, onFileDone })
        逐文件 POST /ingestion/upload  (multipart，单文件 10 分钟超时)
          FormData: file
                   + default_gps / location_poi（可选）
        → 按钮显示「上传中 x/n」；单个失败不中断后续
        → invalidateQueries(['assets']) + notifyImportResult 汇总提示
```

上传依赖 `NEXT_PUBLIC_AMAP_*`（仅选点时）；不选点也可上传。

不用 `/ingestion/upload/batch`：一个请求塞全部文件会撞 Axios 全局 10 秒超时（后端还在导入、前端已报失败），且一个失败全部白传。相册「文件夹导入」与这里共用 `uploadFilesSequentially`。

## 设计决策

### 为什么列表自管累积分页而不是用 `useInfiniteQuery`？

现有 `AssetGrid` 用 page state + `useInfiniteScroll` 手写累积，逻辑直观且已与筛选重置耦合。若大改可迁到 `useInfiniteQuery`，但需保留「筛选变化清空列表」语义。

### 为什么上传走 ingestion 而不是 assets？

后端导入主链路在 ingestion（哈希、缩略图、异步任务）；前端只负责选文件与可选默认 GPS。

## 已知限制

- Axios 默认 timeout 10s，大批量上传可能失败。
- `assetsApi.getTags` 未接线到 UI。
- `export const dynamic = 'force-dynamic'` 写在 client page 上，对 App Router 的实际影响有限（以 Next 行为为准）。
