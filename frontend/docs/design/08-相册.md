# 相册

路由：

- 列表 [`app/(main)/albums/page.tsx`](../../app/(main)/albums/page.tsx)
- 详情 [`app/(main)/albums/[id]/page.tsx`](../../app/(main)/albums/[id]/page.tsx)

## 职责边界

- **负责**：相册 CRUD UI、名称/时间筛选、从 NAS 路径扫描导入到新相册、详情内添加/移除/批量管理素材
- **不负责**：导入流水线内部（后端 ingestion）；素材库级上传（见 [素材库](./07-素材库.md)）

## 列表页

| 能力 | 组件 / API |
|---|---|
| 网格 | [`AlbumGrid`](../../components/albums/AlbumGrid.tsx) → [`AlbumCard`](../../components/albums/AlbumCard.tsx) |
| 筛选 | [`AlbumFilterBar`](../../components/albums/AlbumFilterBar.tsx)：名称、拍摄时间范围 |
| 创建 | [`CreateAlbumModal`](../../components/albums/CreateAlbumModal.tsx) → `albumsApi.createAlbum` |
| 文件夹导入 | [`ImportAlbumModal`](../../components/albums/ImportAlbumModal.tsx) → `albumsApi.importFromFolder` |

`importFromFolder` 实际请求：

```text
POST /ingestion/scan
  source_path, created_by=1, visibility=general
  import_to_album=true
  album_info: { album_name, start_time, end_time }
  default_gps?（可选）
```

成功 toast：「导入任务已启动，素材正在后台导入」——前端不等待扫描完成。

API 适配：[`albumsApi.getAlbums`](../../lib/api/albums.ts) 把后端 `skip/limit` 与 snake_case 封面字段映射为前端 `Album` 模型。

## 详情页

[`albums/[id]/page.tsx`](../../app/(main)/albums/[id]/page.tsx) 一次拉齐：

```text
Promise.all([
  GET /albums/{id},
  GET /albums/{id}/assets?skip=0&limit=1000
])
```

能力：

| 能力 | 说明 |
|---|---|
| 封面与元信息 | 名称、描述、时间范围、数量 |
| 素材瀑布流 | 复用 `AssetMasonry` |
| 编辑相册 | `CreateAlbumModal` 复用为编辑 → `updateAlbum` |
| 删除相册 | `deleteAlbum` |
| 添加素材 | `AssetPickerModal` → `addAssetsToAlbum` |
| 批量模式 | 从相册移除 / 或删除素材本身 |

## 数据流

```text
/albums
  ├─ AlbumGrid → GET /albums?skip&limit&search&start_time_from&end_time_to
  ├─ create → POST /albums
  └─ import → POST /ingestion/scan (import_to_album)

/albums/:id
  ├─ getAlbum → GET album + GET assets
  ├─ update / delete
  ├─ batch add / remove assets
  └─ optional assetsApi.deleteAssets（彻底软删素材）
```

## 设计决策

### 为什么导入挂在相册而不是素材库？

产品语义：「按一次旅行/文件夹建册并灌入」。后端 `import_to_album` 把扫描结果关联到新建相册；素材库上传是散装入库。

### 为什么详情一次拉 limit=1000？

个人相册规模通常可控；省去详情内第二套无限滚动。超大相册会吃内存与首屏时间——若出现需改为分页。

## 依赖

```text
albums pages
  → albumsApi（含 ingestion scan）
  → AssetMasonry / AssetPickerModal / ConfirmDialog
  → sonner toast
```

## 与文档差异

- 旧文档侧重「列表 + 详情网格」；当前已有筛选、创建、文件夹导入、详情批量操作与编辑删除。

## 已知限制

- 导入成功仅表示任务受理，列表可能短暂看不到新素材（需用户刷新或依赖 invalidate 时机）。
- 封面 URL 缺失时回退 `/icon.svg`。
- 详情 `limit=1000` 硬编码。
